title: "Save and Reuse Model Results on the Platform"
description: "Save a model and its result processes in TianGong LCA, inspect the saved results, and reuse them in other models."
---

On the platform, a **Model** organizes processes and their connections, a **Process** holds an input/output inventory, and a **Flow** identifies what is exchanged through inputs and outputs. A result process holds the aggregated inventory calculated from a model for use in subsequent models.

> **Start with the relationship diagram**: [TIDAS: How Models, Processes and Flows Relate](https://tidas.tiangong.earth/en/docs/core-modules/data-relationships/) explains the general object relationships, flows versus exchanges, and supporting flow properties, unit groups, sources and contacts. This page covers the platform's save and reuse workflow.

## Save a model and inspect its results

1. In the model editor, select specific process versions, configure their connections, and set the reference process, reference exchange and target quantity. See [Create My Data](/en/docs/user-guide/create-my-data/) for the full workflow and [Partially Terminated System Modeling](/en/docs/data-collection/case-introduction/model-building/) for a connection example.
2. Click **Save**. The platform runs the calculation and saves the model together with its generated result processes.
3. After saving successfully, open **Model results** to inspect the saved results. A model can generate a primary result and other product results; check the reference product, quantity and system boundary of the result you select.

If you modify a model without successfully saving it again, existing results still describe the last saved calculation, not the current unsaved edits. Save again and check the results after changing process references, connections or the reference target.

## Reuse results in another model

Choose a saved result process in another model's process selector and use the required quantity of its reference product. Before use, check:

- **Exact versions and suitability**: Confirm the process version, flow identity and exact version, measurement basis, and the study's geography, time and technology. Matching names alone do not establish compatibility. See [Using Data](/en/docs/user-guide/data-use/) for version inspection and reference selection.
- **System boundary**: Check which activities the result already includes so you do not count the same activities again as additional inputs.
- **Traceability**: Retain the source model to trace its constituent processes and connections; an aggregated inventory alone cannot reconstruct the complete original model structure.

## Checks before using results

An input/output inventory and life cycle impact assessment (LCIA) indicators are different results. A saved inventory does not guarantee complete characterization-factor coverage for every impact category. Check the coverage notices and [LCIA guidance](/en/docs/user-guide/lcia/) before using the results. A single carbon-footprint value cannot replace a reusable input/output inventory either.

**Saving is not publication.** Review, publication and access conditions follow [Data Review](/en/docs/user-guide/data-review/) and [Permissions and Data Scopes](/en/docs/user-guide/permissions-and-data-scopes/). See [Data Platform Overview](/en/docs/user-guide/data/) to distinguish object types from open, commercial, personal and team data scopes.
